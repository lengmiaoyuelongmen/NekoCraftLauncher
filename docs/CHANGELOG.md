## 2.8.2（2026-11-04）

这一版集中在「装得上、起得来、下得快」：整合包安装更稳、启动不再卡在缺父版本、下载走 aria2 多连接、安装页拆成下载/安装两条进度。

### 逻辑加固

- **启动状态机**：启动失败 / 环境准备失败两条路径都会复位 launching（之前会永久卡在「正在运行」，只能重启启动器）
- **取消真正生效**：spawn 前再查一次取消标志，并删掉 startProcess 里把 launchCancelled 清零的代码（之前点了停止游戏照样启动）
- **下载队列**：activeDownloads 扣减与线程池关闭移入 finally，任一任务异常不再让启动永远等「下载未完成」30 分钟
- **下载完整性**：size 未知时改用 zip 结构校验，截断 / 0 字节的包不再被当成完整；取消异常不再计入失败
- **完整性校验**：库文件按 size 判定（不只看存在），修复成功后作废 5 分钟缓存，不会重复报同一批缺失
- **崩溃诊断误报**：收紧 `OpenGL` / `requires` 等过宽关键词，并按本次启动时间过滤旧 crash-report
- **网卡 / DNS**：重写 netsh 解析（正则取列、跳过环回、按跃点选网卡），DNS 写入改为读回校验而不是猜输出文案；单实例锁区分「已在运行」和「目录不可写」
- **实例文件管理**：同目录 / 子目录判定修正，删除与拖拽失败会如实上报而不是静默成功
- **性能优化备份**：备份损坏时拒绝覆盖并提示，避免把唯一可回滚的记录冲掉

### 安装后可启动性

- **父版本自动补装**：加载器实例的版本 JSON 会 `inheritsFrom` 原版（如 `1.20.1`），原版缺失时游戏直接报「缺少父版本」起不来。现在**导入时**和**启动前**都会检查并自动补装父版本
- **移除「补前置」功能**：删掉模组面板的「检查前置」「补齐前置」按钮、安装后自动补装前置换的递归逻辑、设置页的自动补装开关；只保留只读的「⚠ 缺少前置：xxx」提示

### 整合包安装

- **失败自动重装**：安装失败会清掉临时文件后自动重试一次（最多 2 次），进度页会显示「第 N 次」并重置步骤
- **不再留半成品实例**：解包改为先解到 `cache/modpack-*` 暂存目录，全部成功后再合并进实例目录；两次都失败时回滚——删除本次新建的实例目录和加载器版本目录，不会出现「只有原版、没有加载器或模组」的状态
- **取消也会回滚**：安装过程中点取消同样清理暂存目录和本次新建的实例
- **安装成功删除安装包**：只删除启动器自己下载目录（`downloads/modpack`）里的包；用户自己选的文件保留并提示路径

### 下载进度准确性

- **修复进度条虚标**：原来 aria2/分段下载会用「单个文件的总大小」覆盖整批总量，导致已下载字节超过总量、百分比乱跳。现在分母 = 本批已知大小之和 + 未知大小任务探明后累加的字节
- **百分比与字节双钳制**：进度条限制在 0–100%，字节显示取 `min(已下载, 总量)`；大小完全未知时退回「N/M 个文件」而不是编造字节数
- **索引文件失败自动重试**：整合包索引里的文件下载失败会换官方源再试一轮，日志给出最终成功数

### 安装页双进度条

- **下载进度条**：显示 `已下载 / 总大小 · 当前速度 · 预计剩余 · 当前文件`（如 `8.1 MB / 22.0 MB · 1.5 MB/s · 剩余约 9 秒 · 1.20.1.jar`）
- **安装进度条**：按步骤推进，并显示 `正在进行：安装加载器…` / `已完成：检查整合包`
- 下载数据来自 `DownloadManager` 实时状态（文件数、字节、速度），新增 `totalBytes` 字段用于算百分比与 ETA
- Forge/NeoForge installer 自己打印的 `Downloading library from ...` 也会驱动下载条（不确定进度 + 文件名）

### 内置 aria2 下载引擎

- **引擎随启动器打包**：`engine/aria2c.exe`（aria2 1.37.0-motrix.14，10.77 MB）直接打进 jar，首次使用时解包到数据目录 `engine/aria2c.exe` 并复用
- **不再依赖 Motrix**：没装 Motrix 也能用；解包失败会自动回退内置 HTTP 下载器
- 探测顺序：`-Dneko.aria2` → `ARIA2C` 环境变量 → **内置引擎** → PATH → Motrix 安装目录
- 附带 `engine/NOTICE.txt` 说明 aria2 的 GPLv2 许可与源码地址

### 复用 Motrix 的 aria2 引擎

- **自动检测 aria2c**：从 Motrix 安装目录（`Program Files\Motrix\resources\extra\win32\x64\aria2c.exe`）、`PATH`、`ARIA2C` 环境变量、`-Dneko.aria2=...` 里找，找不到就用内置下载器
- **大文件优先走 aria2**：≥512KB 的任务交给 aria2（16 连接 / 16 分段 / 1MB 最小分段，`--checksum` 直接做 SHA1 校验），失败或取消立刻回退内置 HTTP 下载器
- **断点续传**：aria2 的 `--continue` + `.aria2` 控制文件，中断后重试不会从头下
- **开关**：工具 → 性能优化 → 网络加速 卡片里「使用 Motrix 的 aria2 引擎加速下载」，旁边显示检测到的 aria2 路径

## 2.8.1（2026-11-03，历史记录）

### 修复

- **AI Key 重启后失效**：iApiKey 是 transient 字段，load() 从来没从注册表读回来，所以每次重启 Key 都是空的；更糟的是任何一次 config.save() 都会把注册表里的 Key 覆盖成空。现在启动时从 SecretStore 恢复，测试连接成功会自动保存，输入框留空表示保留已有 Key，并新增「清除 Key」按钮


- **下载页「最新版本」崩溃**：`createBlockIcon` 里三个面的颜色被反编译折进三元表达式，导致 `top/left/right` 恒为 `null`，`Color.web(null)` 抛 NPE
- **「下载 → Minecraft」分类崩溃**：`loadMinecraftVersions` 用 `getChildren().get(0)/get(1)` 强转 `VBox`，实际第 0 个是 `HBox`，必抛 `ClassCastException`
- **确认对话框配色错误**：对话框是独立 Scene，之前只加载了深色样式表；浅色模式下确认框会是「浅色底 + 浅色字」。现在统一走 Theme.applyDialogStyles（基础 + 浅色样式），默认按钮改成主题色，并去掉了默认的蓝色问号图标
- **系统托盘文字乱码**：托盘提示、右键菜单和气泡通知改用 ASCII（Windows 原生托盘路径对非 ASCII 处理不一致），界面内仍然全中文
- **导入整合包重复下载**：导入时会先查找已安装的同版本 + 同加载器实例，命中就复用并跳过游戏/加载器下载，日志提示「已存在实例 …，跳过游戏/加载器下载」

### 重构

- `HelloApplication` 从 9721 行降到约 7800 行（-20%），拆出 20 个组件/工具类

### 启动提速

- **进度回调节流**：下载引擎原来每处理一个文件就回调一次，5147 个资源会往 FX 线程塞几千个 runLater，界面直接卡住；现在 120ms 合并一次
- **资源校验打戳**：资源索引没变就跳过 5147 个文件的逐个校验（ssets/.verified-<index>.stamp），第二次启动约省 1 秒
- **原生库解压改用 ZipFile**：之前用 ZipInputStream 必须把每个 entry 解压才能跳过，31 个 natives jar 扫一遍 442ms；现在只看中央目录，17ms（26 倍），且 dll 大小一致就完全不解压
- **完整性检查复用**：同一实例 5 分钟内的检查结果直接复用，不再每次启动全量重扫
- 日志里加了耗时分解：⏱ 准备耗时：依赖库 x ms / 资源 x ms / 原生库 x ms
