## 1. 外网可达性自检

「检测外网是否可连」按钮：TCP 直连 `公网IP:端口` 先拿即时结论，再尝试用 check-host.net
的境外节点做权威探测（拿到明确结果才采信）。

- 能连上但外部探测本轮不可用 → 如实说「本机直连成功；外部探测本轮不可用，最终以朋友能否连上为准」；
- 连不上 → 「本机直连也没成功，且外部探测不可用（映射大概率没生效）」；
- 外部探测成功时直接给「外部节点已成功建立 TCP 连接」或「外部节点连不上」。

不把「探测失败」伪装成「一定能连」。实测：`1.1.1.1:53` → 可达；本机公网 `:25599`（未映射）→ 不可达。

## 2. 同时开多个服 + 每服一个标签页

- 历史列表每行独立启停，`Map<id, RunningServer>` 管理多个进程；
- 日志区改成 `TabPane`：启动一个服就多一个标签页（标题带端口），退出后标「已退出」保留内容；
- 状态栏显示「运行中：N 个 · id1 / id2」。

冒烟实测：同时创建并启动 25599 与 25600 两个服，两边日志都出现 `Done (`，互不干扰，先后 `stop` 都干净退出。

## 3. 页面内控制台

标签页底部是命令输入框，直接往服务端 stdin 写：`list` / `op 玩家` / `stop` 都能用，
回显会带 `> 命令` 前缀，方便对着日志确认。

冒烟实测：对两个运行中的服各发一次 `list`，两边都回了玩家列表；用 `stop` 正常关服，
10 秒没退再强制结束，避免卡在保存世界。

## 实现说明

服务端输出改为**重定向到 `server-console.log` 再由 tail 线程追读**，而不是直接读管道 ——
管道缓冲区写满会让服务端卡死，日志文件不会；进程退出后再补读一轮，`Done` / `Stopping` 不丢。
