# 界面文案（i18n）约定

> 状态：导航层已全量双语；正文按页推进，欠账 **2175** 条，只降不升。

## 1. 两种写法

**壳层（有语义 key）**——顶栏、页签、按钮、空状态这类要长期维护的文案：

```java
I18n.t("nav.launch", "启动")          // 英文缺失时回退到第二个参数
```

**正文（中文原文当 key）**——逐页推进时的低摩擦写法：

```java
I18n.t("添加已有文件夹")               // 英文缺失时回退到 key 本身 = 中文
```

对应的英文包：

```properties
添加已有文件夹=Add folder
```

好处是加文案不用先起名字；代价是 key 就是中文，改中文等于改 key，所以这一类只用于
「原文稳定、不会再改」的界面标签。

## 2. 语言包里的坑（踩过一次）

`.properties` 的 key **不能含未转义的空格** —— 解析器会把空格当分隔符：

```
★ 只看收藏=★ Favourites only        ← key 实际是「★」，查不到
★\ 只看收藏=★ Favourites only       ← 正确，空格要写成 \ 
```

带空格的中文 key（如「每个实例独立的 mods / config / saves」）必须把空格转义。

## 3. 守卫

| 东西 | 作用 |
|---|---|
| `scripts/i18n-report.ps1` | 清点未走 i18n 的中文字面量，导出 `build/i18n-report.csv` |
| `scripts/i18n-baseline.json` | 基线总数，`-Check` 时高于它就 exit 1 |
| `I18nCoverageTest` | 单测里复算同一口径；另外校验中英 key 对齐、导航层条目无中文 |
| `scripts/ci.ps1` | 第 2.5 步跑 `i18n-report.ps1 -Check` |

口径：`I18n.t("...")` 与 `I18n.t("...", "...")` 两种包裹形式都算「已处理」，其余中文字面量算欠账。
